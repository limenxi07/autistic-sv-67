**Goal:** Add robust Task 2 image perception to the frozen P2 planner while retaining its Task 1 results and meeting the complete single-CPU episode and source-size limits.

**Architecture:** A small CNN parses cells; an observation bridge and persistent tracker maintain symbolic state from images and metadata. A deadline adapter reuses P2 planning and reference replay, while independent visual checks detect wrong reconstructions. Oracle-perception diagnostics isolate adapter failures before model training.

**Tech Stack:** Existing locked Python environment, NumPy/Pillow, CPU Torch 2.7.0 for deployment/export, public Grid Adventure APIs, unittest and the existing subprocess benchmark infrastructure. M5080 training uses a separately verified compatible environment.

**Spec:** `docs/superpowers/specs/2026-11-09-v3-vision-design.md` (read before execution).

## Global Constraints

- Tasks 1/2: 150 turns, 5 seconds for the whole episode, 1.5 GB memory, one CPU core, no GPU at submission time.
- Submission source must be below 2,000,000 bytes, including embedded model and loader. Target at most 1,600,000 bytes to leave room for fixes.
- Retain Python 3.10 grammar and prelude/no-module-registration loader checks. Development/deployment compatibility uses the repository's pinned CPU Torch 2.7.0 and NumPy/Pillow environment.
- Use public assets, assignment/tutorial, public constructors and black-box API observations. Do not inspect engine implementation source. No network, external asset reads, or model downloads in the submitted agent.
- Preserve P1/P2 source and evidence bytes. Build V3 in new files; maintain Task 1 as a separate usable submission.
- Archive dataset generation scripts, training code, configurations, checkpoints, manifests and generated datasets as required by the assignment's supplementary-files rule.
- Task 3, learned search, policy learning, world models, and expanding P2's supported simulator schema are outside the initial release. Report boss diagnostics separately if time remains.
- One clock: initial planning through t0+3.00 s, verification/repair through t0+3.50 s; target every complete qualification episode <4.25 s and <1 GB RSS. Model loading/parsing consumes this budget. Conservative cold import-to-terminal must fit 5 s before claiming that property.
- Do not stage unrelated pre-existing files or alter frozen archives. At execution, choose an isolated workspace only if it includes all currently untracked required inputs; otherwise document the same scoped shared-checkout approach used for P2. No automatic remote submission.

## Review Focus

- Identity-sensitive inventories/effects: oracle-perception equivalence must compare against the original environment, including re-identification and action order (Task 1).
- Leakage through near-duplicate sprites, backgrounds or rendering roots: manifests must attribute every source group and reject cross-split use (Task 2).
- High confidence on an incorrect board: a simulator-valid plan must remain conditional on the parse; counter-only checks cannot replace visual localization (Task 4).
- Later overlapping sprites: preserve hidden layers from history and expose unresolved ambiguity rather than manufacturing an exact current state (Task 4).
- Cold load, variable crop batches and nested deadlines: final exported agent must meet loader, numerical-parity and complete-episode constraints (Tasks 3, 5, 6).

## File responsibilities and stable interfaces

All files below are new unless explicitly called existing. Do not refactor P2 as part of this work.

| File | Responsibility |
|---|---|
| `agents/v3_types.py` | NamedTuple records shared by runtime modules; no Torch import |
| `agents/v3_bridge.py` | Grid geometry, metadata decoding, persistent local IDs, semantic-state reconstruction |
| `agents/v3_planner.py` | Versioned P2a-derived backend with original deadlines, optional P2b mode; record parent hash |
| `agents/v3_perception.py` | Batched preprocessing, CNN loading/inference, calibrated cell probabilities |
| `agents/v3_tracking.py` | Prediction, visual/metadata comparison, bounded board hypotheses and reconciliation |
| `agents/v3.py` | Public `Agent`, structured/image dispatch, episode budget and diagnostics |
| `tools/v3_data.py` | Asset-group splits, public-renderer dataset generation, immutable data manifests |
| `tools/train_v3.py` | Small CNN training, evaluation, checkpoints and reproducibility records |
| `tools/export_v3.py` | Pinned CPU Torch export and eager/export parity checks |
| `tools/benchmark_v3.py` | Image/oracle/structured workers, independent ground-truth scoring, resource measurements |
| `tools/package_v3.py`, `tools/qualify_v3.py` | Self-contained source assembly, strict promotion reports and supplementary archive |
| `tests/v3_fixtures.py`, `tests/test_v3_*.py` | Independent expected states, contracts, leakage, tracking, export and harness tests |
| `artifacts/v3/` | Immutable manifests, models, datasets, reports, candidate sources and provenance |

Define these records in Task 1 and keep signatures consistent:

- `EpisodeBudget(started_at: float, initial_deadline: float, cutoff: float)`.
- `CellScores(probabilities: object, width: int, height: int)`; probabilities are a NumPy float array `[height, width, 14]`, fixed class order from the design's inventory list.
- `BoardHypothesis(state: GridState, confidence: float, unresolved: tuple)`; unresolved identifies semantic cells/resources that are not observationally established. Confidence is a calibrated ranking aid, not a proof.
- `ObservationCheck(consistent: bool, changed_cells: tuple, mismatches: tuple)`; mismatches records independent observed-versus-predicted discrepancies.

Runtime uses stable local identities in `GridState`; no hidden environment handles appear in these records. Development-only oracle functions live under tools/tests and are excluded from the package.
