# Conditional resource-event search experiment

Activate only if bounded primitive-cap experiment still loses. Keep parent primitive search unchanged as the control and as first pass; retain a verified incumbent independently. Invoke event search only after a nonwinning cap/exhausted result, during the same original call and initial deadline. No WAIT dispatch between these passes, hence no root restart/lost turn. Existing supported schema/fast_step/read_state unchanged.

Events: consumption of a specific gem/coin/key/power slot, removal of a particular locked door, changed box configuration, or terminal win. Coordinates only guide local ordering. Each endpoint carries the entire FastState, exact score, and full primitive path. No mask/count-only state merging. Local paths may pick up incidental resources, activate/expire effects, push boxes and open doors; full endpoint states retain each consequence. Phasing paths must survive expiry under fast_step; full primitive winning replay remains the independent gate.

Bounded experimental worker: global priority frontier <=1024 and records <=8192; one local query at a time, <=1024 frontier/8192 records, depth <=24, up to four exact endpoint alternatives per resource goal. These are heuristic truncations, not completeness/dominance claims. All seven primitive actions remain eligible (including WAIT). Losing states are excluded. Local caches are scoped to one exact board/root; no history is rebound by renaming IDs. Queries and ordering use the same absolute deadline, checked inside loops. No additional clock on repairs.

Primitive win remains preferred: resource search only rescues failure, so existing winning paths and rewards remain the baseline. Proposed full primitive sequences go through public verify_plan before dispatch or incumbent installation. Invalid/deadline candidate cannot replace any verified incumbent. Candidate outcomes determine acceptance; unsuccessful source checkpoints are retained.
